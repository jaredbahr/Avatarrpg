# Pipeline proof plan

**Status:** draft for the owner, 2026-11-14. Answers the "Current goal" in `CLAUDE.md`: before new regions start,
prove the content, art, story and scale-and-saves pipelines on one small real region. Numbers below were measured on
`main` at `4f48b1b` unless marked **unknown** (measure in the trial) or **unverified**.

## Summary

| Pipeline     | Today                                                                                                             | Biggest gap                                                                                                                        |
| ------------ | ----------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------- |
| Content      | Maps, NPCs, story, fights are data in `src/content/` and validated; no `src/core/` change is needed for a region. | About 12 registration points across content, scripts and app; per-map special cases in `src/app/`; regions and level bands absent. |
| Art          | Fixed PixelLab recipes (ADR 0103, 0107) with ledgers and 3x checks.                                               | Each map's board is a hand-written 400–1,150 line script; no per-region cost roll-up; credit price in money unknown.               |
| Story        | One validated graph, a condition DSL, generated story diagrams, a writing guide.                                  | No story bible, no flag registry (#493), no cross-region continuity test beyond the demo route.                                    |
| Scale, saves | One JS bundle at 382.8 of 410 KB gz; versioned saves with a kept golden corpus.                                   | Everything (all story, all maps' scenes) loads at boot; the audio family has room for less than one more area track.               |
| Devices      | iPad landscape tuned and in CI; mouse wheel zoom and hover work.                                                  | No keyboard play, no gamepad, no desktop mouse e2e project; the Steam route is untested.                                           |

## 1. Content pipeline

### What a region touches today

A region here means one or more explore maps, their NPCs, story nodes and fights. Traced from the demo route:

| Step                       | Files                                                                                                                                 | Kind                    |
| -------------------------- | ------------------------------------------------------------------------------------------------------------------------------------- | ----------------------- |
| Map rules (rows, legend)   | new file in `src/content/maps/` (pattern: `village.ts`, `combat.ts`), added to `ALL_MAPS` in `src/content/index.ts`                   | data                    |
| Exits, triggers, edges     | `src/content/maps/world.ts` (`connectAct1`: `route()`, `crossing()`, conditions)                                                      | data, Act 1 specific    |
| NPCs and routines          | `src/content/residents/` (`baDan.ts`, `routines.ts`), map `npcs`                                                                      | data                    |
| Story nodes                | new file in `src/content/story/`, added to `ALL_STORY` in `index.ts` and to `STORY_GROUPS` in `scripts/docs/story-graph.ts`           | data plus a script list |
| Party voices               | `src/content/story/partyVoices.ts` (wrapped by `withPartyVoices`)                                                                     | data                    |
| Enemies, encounters        | `src/content/enemies.ts`, `src/content/encounters.ts` (variants, reinforcements)                                                      | data                    |
| Abilities (if new)         | `src/content/abilities/<element>.ts`; a projectile also needs `SHOT_LOOKS` in `src/app/anim/choreography.ts`                          | data plus app           |
| Top-down scene             | `TOPDOWN_SCENES` in `src/content/topdown.ts`; layout in `src/content/topdownLayouts.ts` and `src/content/scenes/<map>.topdown*.ts`    | data                    |
| Ground bake                | a board in `scripts/art/topdown/boards/` (registered in `boards/index.ts`), packed by `pack-ground.ts` to `public/art/topdown/<map>/` | script code             |
| Figures, portraits, sounds | `src/content/assets/manifest.ts`; `topdownSheets.ts` is generated by `scripts/art/topdown/pack-sheets.ts`                             | data, generated         |
| Music                      | `MAP_MUSIC` and `MUSIC_TRACKS` in `src/content/music.ts`                                                                              | data                    |
| Tests                      | `progression.test.ts` routes, golden save checkpoints in `scripts/saves/make-golden.ts`                                               | tests                   |

**`src/core/` needs nothing** for this; `grep` finds no map, encounter or boss id under `src/core/`.

**`src/app/` and `src/render/` still hold per-map or per-unit special cases** a new region may have to copy:
`combatGuidance.ts` and `CombatScene.ts` (`enc_forest_road`, the guided fight), `ExploreScene.ts` (`forest_road`),
`audio/environment.ts` (`ba_dan_village` only), `world/practice.ts`, `village/VillageLife.ts` (a story node id),
`exploreMarkerScale.ts` and `render/drillerGrounding.ts` plus both backends (the Driller). A new boss with a large
footprint may need render code like the Driller's; **unknown** until the trial's boss is drawn.

**Not built yet:** ADR 0011's regions with `minLevel`/`maxLevel`, region membership on maps, and the region-graph
rewrite of `progression.test.ts` (roadmap W1, W6). Exits and triggers exist (ADR 0017); the roadmap's W checklist is
not ticked for them and should be brought up to date.

### Fixes

- [ ] **Region manifest:** one `src/content/regions/<id>/index.ts` exporting maps, story, residents, encounters,
      music rows and scene sources, with `index.ts`, `STORY_GROUPS` and `TOPDOWN_SCENES` built from the list of regions.
      Removes most registration points.
- [ ] **Move special cases into data:** guided-fight steps on the encounter, environment audio on the map, projectile
      look on the ability. Exit test: `grep` for map and encounter ids in `src/app` and `src/render` finds none.
- [ ] **Region template and generator:** `scripts/content/new-region.ts <id>` writes the manifest, an empty map, a
      two-node story file and a board stub, all passing `validateContent`.
- [ ] **Regions and bands (W1, W6):** level band per region, world-graph checks in `validateContent`.
- [ ] **Board authoring:** extract the shared parts of `boards/baDan.ts`, `forestRoad.ts` and `quarry.ts` so a new
      board is mostly a declaration; measure lines per board before and after.

### Estimate per region (to be replaced by the trial's measurement)

A rough sum for a small region of two maps, three new enemy types, two new NPCs and their portraits, using the unit
costs above: tilesets 4 × 15, objects 25 × 5, three enemies × (base + idle, walk, attack, hit, knockout at about
24 each) about 360, two NPCs about 100, five portraits × 3 tries × 6 about 90, effects and sounds about 20. **About
750 credits, ±50%; unknown until measured.** Owner review rounds and retakes are the likely swing.

### Gaps

- [ ] A per-region cost roll-up: tag every ledger job with a region id; `ledger_audit.py` prints a total per region.
- [ ] The ledgers are split (`prototypes/topdown/ledger.json`, `art/source/forest-road-g1/ledger.json`,
      `art/source/fx-g1/ledger.json`); one ledger, or one audit over all of them.
- [ ] A written model sheet per recurring character (description, palette, seed, character id) so a retake months
      later matches; the ledger holds this per job but nothing collects it per character.
- [ ] An on-model check that a script can run (palette distance to the model sheet, foot line, size), so the 3x
      check is a confirmation, not the only gate.
- [ ] Animation list per figure written down (which clips every enemy and NPC must have), so a region's art order
      can be generated from its encounter data.

## 3. Story workflow

### Today

- **Graph:** `StoryNode` kinds in `src/core/types.ts`; nodes per file in `src/content/story/` (111 nodes, 4 fights, 8
  branches, 4 choices across six files, per `docs/story/README.md`).
- **Gates:** `Condition` (`src/core/story/conditions.ts`), describable to the player; nation standing behind
  `standing.` with its own helpers.
- **Validation:** `validateContent` (`src/content/schemas.ts`) checks references and that every node is reachable from
  the entry or an NPC; `conditionReferences.test.ts`; `progression.test.ts` walks every route for level fit.
- **Readable output:** `npm run docs:story` generates the Mermaid diagrams in `docs/story/` (checked with `--check`).
- **Voice:** `docs/writing-guide.md` (situation first, people responding to each other, honest fiction, review).
- **Continuity across saves:** `src/core/save/continuity.test.ts` checks a loaded save keeps the same objective and NPC
  scenes, for the demo route only.

### What is missing for a forty-hour plot

- [ ] **Story bible** (`docs/story-bible.md`, owner-owned): premise, acts and regions in order, each character's arc,
      what each knows when, places, factions, open threads. Claude reads it before drafting; it changes only with the
      owner's yes.
- [ ] **Flag registry** (#493): `src/content/flags.ts` declares every flag with its owner region, meaning and type;
      `validateContent` rejects a flag that is read but never set, set but never read, or not declared.
- [ ] **Cross-region continuity test:** for each region entry, the set of flags that can be true or false there,
      generated from the graph; a later region may only read flags its entry set can hold.
- [ ] **Character availability:** who is in the party or alive at each node, so a line never has an absent speaker
      (the writing guide already asks for this by hand).

### Proposed owner and Claude loop

| Step | Who    | Output                                                                           | Gate                                                            |
| ---- | ------ | -------------------------------------------------------------------------------- | --------------------------------------------------------------- |
| 1    | Owner  | Beats for the region: a short list in plain words, plus any must-keep lines      | none                                                            |
| 2    | Claude | Beat sheet: beats mapped to nodes, choices, flags read and set, fights, speakers | owner approves the beat sheet (one reply)                       |
| 3    | Claude | Draft scenes as story data, flags declared, diagram regenerated                  | `validateContent`, flag registry, progression, continuity tests |
| 4    | Claude | A play-through capture of every new scene and both sides of each choice          | writing-guide review                                            |
| 5    | Owner  | Notes on the capture or the generated diagram                                    | owner's yes; then the PR merges                                 |

## 4. Scale and saves

### Today (measured)

- **JavaScript:** one main chunk, `index-*.js` 378.7 KB gz, plus Pixi's lazy `browserAll` 3.9 KB; **382.8 KB of the
  410 KB budget** (`scripts/check-bundle-size.mjs`, ADR 0109). The only dynamic import in `src/` is the dev-only
  content validator in `src/main.ts`.
- **Content's share** (`npm run bundle:report`, estimates): `src/content` about 59 KB gz in all, of which story 14.9,
  abilities 9.5, assets 6.1, maps 5.4, residents 2.6.
- **Map scenes** are JSON assets fetched at boot, all five at once (`loadTopDownPresentations` in
  `src/content/topdown.ts`), not bundled.
- **Assets:** precache 10.43 of 25 MB; top-down art family 4.65 of 6 MB; audio family 3.35 of 4 MB, of which music is
  3.3 MB streamed, not precached (`scripts/precache.mjs`). One more area track (0.5–1.1 MB each today) breaks the audio
  budget.

**Risk:** story text, maps and residents grow with play time. A straight-line guess from the demo (about 60 KB of
content for a route of 30–40 minutes) puts a forty-hour game far past any single-bundle budget. The exact growth is
**unknown**; the trial measures KB per region.

### Plan: load per region

- [ ] Split content into a **core bundle** (rules, abilities, party, shared UI) and **one data chunk per region**
      (`import()` of the region manifest from section 1), loaded on entering the region and when a save is loaded.
- [ ] Scenes, figures and portraits: load the current region's and its neighbours' instead of all at boot.
- [ ] **Offline:** precache the core and the current region; runtime-cache the rest on first visit
      (`workbox` `CacheFirst`). A family tablet then plays offline anywhere already visited. **Decision for the owner:**
      precache every region (simple, larger install) or visited regions only.
- [ ] **Budgets:** the JS budget applies to the core plus the largest region chunk; a per-region asset budget replaces
      raising family budgets each time. Both need an ADR (engine and budget change).
- [ ] Issue #526 (lazy-load scenes and panels) is the first step and already open.

### Saves today

- `SAVE_FORMAT_VERSION = 5` in `src/core/save/serialize.ts`; `migrate()` steps 1→2→…→5 on raw JSON; a newer save
  is refused with a clear message.
- Load-time repair: `src/core/save/reconcile.ts` rebuilds kits and world state against current content and warns on a
  missing map.
- **Golden corpus:** `src/core/save/fixtures/golden/v5/`, 18 saves (nine checkpoints from new game to home, at 1 and
  4 players), made by `scripts/saves/make-golden.ts`; `golden.test.ts` keeps every old version folder forever.
- Plus `fuzz.test.ts`, `serialize.test.ts` (mid-battle round trip), `sizeBudget.test.ts`, `continuity.test.ts`.

### Plan: a region-one save loads years later

- [ ] **Release fixtures:** each tagged release adds its golden saves under `fixtures/golden/<version>/`, never
      regenerated; CI loads every one and plays a few commands from it.
- [ ] **Content ids are forever:** a story node, map, NPC or encounter id that a save may hold is never deleted or
      renamed; removal goes through an alias table that `reconcile` reads. A test diffs ids against the last release.
- [ ] **Saves outside the browser:** localStorage can be wiped (iPad storage pressure, a PC browser profile reset).
      Keep JSON export prominent; consider a reminder after each region.
- [ ] Save size per region: `sizeBudget.test.ts` today; extend with one checkpoint per region.

## 5. Devices

**Shared iPad, landscape:** tier 1 in `docs/device-matrix.md`, WebKit `ipad-landscape` in CI (with the known red runs,
#423, #644). Keep it the first target.

**PC window for Steam Remote Play,** audited in `src/app/`:

| Area        | Today                                                                                         | Gap                                                                                                 |
| ----------- | --------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------- |
| Mouse       | Pointer events throughout; wheel and ctrl+wheel zoom (`input/pointer.ts`); combat hover ghost | No desktop mouse project in `playwright.config.ts` (only touch profiles)                            |
| Right click | Context menu suppressed (`pointer.ts`)                                                        | Not mapped to anything (cancel would be natural)                                                    |
| Keyboard    | Enter and Space on focusable controls (`ui/dom.ts`); Escape cancels aim or walk               | No keys for end turn, ability slots, camera pan or dialogue advance; #491 (keyboard-only play) open |
| Gamepad     | none (`getGamepads` not used)                                                                 | See below                                                                                           |
| Window size | layout fits any viewport; desktop is tier 2                                                   | 16:9 and 1080p window not tuned or tested                                                           |

**Gamepad:** **unverified.** Remote Play Together guests send keyboard, mouse or controller input to the host if the
host allows it, and guests on a phone or TV usually have only a controller or touch. If the friends play from phones,
gamepad (or Steam Input mapping a controller to mouse and keys) matters; check with the actual friends first.

**Adding a browser game to Steam (unverified, test in the trial):** "Add a Non-Steam Game" pointing at Chrome or Edge
with launch options such as `--app=<game URL>` and a dedicated `--user-data-dir` (keeps saves in one profile). Not
verified here: whether Remote Play **Together** invites work for a non-Steam shortcut (Steam documents it for Steam
games), whether the Steam overlay attaches to a Chromium window, and whether a packaged wrapper (Electron, Tauri) would
be needed instead.

## 6. Proof trial

A small region after the walk home, built through the loop above. Story content is a placeholder for the owner.

| Item    | Proposal                                                                                                        |
| ------- | --------------------------------------------------------------------------------------------------------------- |
| Size    | Two explore maps (a hub about Ba Dan's size, 24 × 16, and a smaller route map), one combat board                |
| Beats   | Owner supplies about 5: arrival, a person with a problem, a choice with two outcomes, a fight, a return or hook |
| Fights  | Two: one ordinary with a new enemy type, one harder with a combo set-up; no new boss, to keep render code out   |
| New art | Two tilesets, about 20 objects, two enemy types and one NPC with full clips, three portraits, one area track    |

### What to measure

- Hours from owner beats to merged region, split by pipeline; owner review rounds; Claude sessions used.
- PixelLab credits per asset type (from the region-tagged ledger), and retakes per figure.
- Files touched outside `src/content/`, `public/art/`, `scripts/art/topdown/boards/`; lines per new board.
- KB gz added to the bundle (before the split) and to each asset family; region chunk size (after).
- Load time of the region on the iPad (cold and warm); **unknown today**, no baseline recorded.
- Saves from the demo route and from each trial checkpoint load on the trial build and on the build after.

### Pass bar

| Pipeline | Pass                                                                                                                                                  |
| -------- | ----------------------------------------------------------------------------------------------------------------------------------------------------- |
| Content  | Zero changes in `src/core/`; zero map or encounter ids added to `src/app/` or `src/render/`; region added by its manifest plus one list entry         |
| Art      | Every figure on-model at the first owner review or one retake; region cost within ±25% of the estimate made before generation                         |
| Story    | Beat sheet approved in one round; validators, flag registry and continuity tests green; no line by an absent speaker in review                        |
| Scale    | Region code and data load on entry, not at boot; core JS does not grow by more than the shared code the region adds; offline play of a visited region |
| Saves    | Every v5 golden save and every demo-route save loads and reaches the trial region; new checkpoints added to the corpus                                |
| Devices  | Trial played start to end with mouse and keyboard in a PC window and once over Steam Remote Play; iPad landscape still passes CI                      |

### Order of work

1. Region manifest and flag registry (no behaviour change); story bible skeleton for the owner.
2. Per-region loading behind the manifest, with its ADR; release fixtures and the id-forever test.
3. Keyboard and right-click basics; a desktop Playwright project.
4. The trial region through the loop, measured.
5. A short report: measured cost and time per region, and what to fix before region three.
